## 启动

同条件 FreeDOM 并行建图演示：

```bash
cd /home/a/AstraDroneOpen
bash scripts/run_sh/half_warehouse_freedom_demo.sh
# 无图形界面可追加 --headless；手动控制行人可追加 --manual-pedestrian
```

这个入口调用下文同一半仓库运行器，仅额外启动现有 `freedom/astra_mid360_baseline.launch`。半仓库几何、FAST-LIO、自动行人、探索选点、控制/避障、0.60m/s 双速度上限、0.80m 净距、90% 在线验收、550 仿真秒预算均沿用当前配置；不向导航地图话题写入 FreeDOM 输出。FreeDOM 读取同航次 `/cloud_registered_body` 和 `camera_init→body` TF，独立保存 `*_freedom_static_map_point.pcd`；原维护地图仍保存为 `*_final_map.pcd`。地图算法本身及并行计算负载不同，因此墙钟耗时不能被当作只有算法参数变化的加速对照。

默认完成返航/保存后会自动关闭本轮 Gazebo、RViz 和 ROS；只有显式传入 `--keep-open` 才保持窗口。FreeDOM 入口在系统支持时用 `systemd-inhibit` 阻止运行期间普通自动休眠；意外强制休眠后，运行器的 2400 秒总保护计时仍累计休眠时长，醒来会保存部分地图并清理进程，不会将中断记作任务成功。电脑关机或休眠期间仿真本身无法继续推进。

结果中 `task_success` 表示返航驻留且原维护地图保存，`freedom_map_saved` 表示 FreeDOM 地图保存，`freedom_demo_success` 要求两者同时成立。`*_shelf_audit.json` 与 `*_freedom_shelf_audit.json` 使用同一货架碰撞盒侧面参考、各自初始位姿坐标对齐；这两个支持率不是全三维完整率。对应图片是 `*_map_and_trajectory.png` 和 `*_freedom_map.png`。初始对齐只供离线评价，不参与机载规划。并行保存地图的点数或单次支持率不能证明动态残影消除效果或统计优劣。

在有图形界面的终端可分别用 `pcl_viewer half_warehouse_demo_runs/warehouse_half_时间_freedom_static_map_point.pcd` 和 `pcl_viewer half_warehouse_demo_runs/warehouse_half_时间_final_map.pcd` 查看原始三维点云；两张原始 PCD 的坐标系分别为 `camera_init` 与 `map`，不能直接叠放，统一世界坐标预览见上述 PNG。

先正常结束其他ROS/PX4/Gazebo演示，再运行：

```bash
cd /home/a/AstraDroneOpen
bash scripts/run_sh/half_warehouse_exploration_demo.sh
```

默认打开Gazebo和RViz；自动等待地面/航向稳定、相对起飞1.2m、自主选点、观察、返航驻留并保存。运行副本会加入一名可移动的站立行人。无人机导航与总水平速度上限目前为0.60m/s（此前测试过0.80m/s），安全净距仍为0.80m，风险停车和紧急阈值不变。此场景不启用语义网络或回环。

默认模式中，行人先静止；无人机起飞并接近后，行人沿左侧通道自动走一轮，结束后可键盘接管。手动模式会跳过自动行走，便于启动后直接控制：

```bash
# 主终端：行人保持静止并立刻开放键盘控制
bash scripts/run_sh/half_warehouse_exploration_demo.sh --manual-pedestrian

# 第二个终端：控制0号行人
bash docs/演示启动命令/行人键盘控制.sh
```

W/S沿世界Y轴、A/D沿世界X轴，空格停止，Q退出；键盘命令超过0.4秒没有刷新会自动停。行人节点按仓库墙体/货架碰撞盒拒绝穿障移动。移动的是站立模型，不是骨骼动画；碰撞盒只保护行人移动，不提供给无人机感知或规划。默认自动行走结束后也可在第二终端运行同一键盘命令。

```bash
# 无图形界面
bash scripts/run_sh/half_warehouse_exploration_demo.sh --headless

# 完成返航保存后保留窗口，直到Ctrl-C
bash scripts/run_sh/half_warehouse_exploration_demo.sh --keep-open

# 两目标短程功能检查，明确为部分探索
bash scripts/run_sh/half_warehouse_exploration_demo.sh --return-after-goals 2 --test-seconds 360
```

首次构建方式与[小办公室说明](SMALL_INDOOR_DEMO_CN.md)相同。入口共享小室内运行器和速度坐标转换节点，通过`--scene cangku-half`选择场景；默认小办公室入口仍选择office。导航/总水平速度上限为0.60m/s，安全净距0.80m保持；按用户允许适当放宽验收的要求，半仓库在线已测表面质量门限由95%改为90%。FAST-LIO、证据地图、搜索及飞控安全链沿用已有实现；探索阶段调度增加以下证据策略。

探索预算550仿真秒或1200墙钟秒，补扫预算240仿真秒，返航超时600仿真秒；运行器总墙钟保护2400秒。这些是后备上限，不是必须等待的时长。预算退出是部分探索，不能从保存成功推断完整覆盖。任务成功表示确认返航驻留并保存，分别读取`exploration_complete`、`coverage_complete`判断探索报告。

## 提速与有效补扫

当前半仓库导航及总水平速度上限为0.60m/s，已在2026-10-16的205003 FreeDOM 同航次 headless 完整任务中运行验证。更早的提效任务使用0.80m/s，前视距离2.0m，规划3Hz，到达后观察1秒；后备任务预算550仿真秒（此前0.40m/s、1.2m前视、2Hz、2秒观察、600秒预算）。比例增益保持0.45，2.0m前视距离保留，速度由导航和总速度上限限制；前视航段仍逐段检查已知安全空间，转弯处可缩短。结果是否保持质量须结合实际自由面积、在线已测表面证据和离线货架侧面代理检查，不能仅按速度倍率推断。

共用探索器保留三处修复：

- 低收益转补扫使用任务累计成功观察至少3次，不再要求同一个90秒窗口完成3次长途观察。
- 补扫候选相对初次观测位置至少满足0.75m独立基线，再预留实际到达容差；到达误差范围内的视角也不能落回已见扇区。
- 聚合采样保留每个区域的缺失体素数量，优先修复密集缺失。权重仅用于选点，实际质量仍由原独立扫描/视角证据计算，每体素仍需至少3次独立扫描、2个视角扇区和0.75m观测基线。

半仓库增加适度放宽的演示验收：累计到达至少6个目标、任务至少180仿真秒、已测表面至少1000体素；最近60仿真秒新增已知射线平面面积低于max(2m², 1%累计已知面积)，且在线质量≥90%的联合条件连续保持10仿真秒。使用推进的扫描时间戳，过时/暂停/不安全时清除窗口；内存容量耗尽不能通过。达标可提前返航，退出原因`observed_map_accepted_partial`，`exploration_complete=false`、`coverage_complete=false`。只降低演示验收比例，不降低独立扫描/视角证据要求，也不代表未见区域或全三维完整。

前3轮95%验收的自适应阶段调度没有证明提速，最终撤下强制阶段交接和过时目标退役；新门控只有已满足90%质量后才结束任务，不强迫提前转补扫。负结果和加载源码在[提效验证报告](../../../../docs/演示验证/2026-10-16_探索提效/方案与验证.md)中保留。原严格收敛、预算、候选耗尽和故障分支分别报告；550秒仍是后备预算。

结果JSON增加`configuration`、`run_options`与`timing`，记录实际速度/安全/质量/预算参数、界面模式及启动/返航前/返航驻留墙钟。新增`map_quality_accepted`单独表示最终在线质量达标，与返航保存成功及探索完整标志分开。离线货架侧面支持率仍单独审计，其原验收比例未降低。批量性能测试用`--headless`，演示保留默认窗口；比较时同时报告仿真秒、墙钟秒及地图质量。`inspection_cells`是旧近场覆盖计数，当前表面补扫是否发生以`mission_phase`/状态历史为准。
