# 无人机三维主动探索算法与开源项目调研

调研日期：2026-10-17。范围：核对论文/作者项目页、GitHub README，以及本项目当前源码和配置；未克隆、编译或运行下列外部项目。表中“适配度”是工程判断，不是实测性能。

## 本项目的比较基线

本项目 ROS1 Noetic + PX4/MAVROS + FAST-LIO/MID-360 已能输出三维点云，但 `warehouse_explorer.py` 将点云按飞行高度截取为二维规划层，以固定高度选择 frontier；状态字段也明确 `coverage_complete=False`，验收范围是“已观察到的、可达的固定高度空间”，并非整个仓库的三维表面。因此，引入三维探索的关键是**未知/自由/占据体素与真实传感器视线**、三维候选视点、完整机身扫掠碰撞检查和三维验收，而非仅替换选点公式。已有动态行人实验还要求将动态点从静态地图证据中区分，并继续保留返航与停机逻辑。

## 候选算法与 GitHub 项目

| 项目 | 方法与优点 | 局限/接入工作 | 本项目适配度 |
|---|---|---|---|
| [SHIELD](https://github.com/LiuZhenchang/SHIELD)，[论文](https://arxiv.org/abs/2512.23972)，2025 预印本 | 面向 LiDAR 无人机；观测质量占据图、混合 frontier、球面投影射线处理稀疏回波。与 MID-360 的非重复扫描问题相关；Ubuntu 20.04/ROS Noetic。 | 示例依赖 MARSIM、NLopt、LKH；须接 FAST-LIO 位姿/逐帧点云，标定扫描几何与时间。**无回波方向不能直接断言为空闲**，需依据有效测量与传感器模型。 | **高，首选可复现算法基线**；先在隔离工作区复现，再接本项目。 |
| [FALCON](https://github.com/HKUST-Aerial-Robotics/FALCON)，[论文](https://arxiv.org/abs/2407.00577)，T-RO 论文 2024/卷期 2025 | 利用在线覆盖路径引导大范围探索，兼顾全局访问顺序与局部重规划；EPEE 支持 PCD/PLY/STL 环境，适合做半仓库统一场景基准。ROS Noetic。 | 构建链较重（Open3D、NLopt、CUDA 渲染等）；自带仿真/轨迹接口与本项目不同。导入静态 PCD 作为仿真环境不等于在线接入 MID-360。 | **中高（算法/基准），中（直接集成）**；适合作为强对照。 |
| [FUEL](https://github.com/HKUST-Aerial-Robotics/FUEL)，2021 | 增量 frontier 结构与分层规划，ROS Noetic 有作者示例，便于比较运行时间与探索效率。 | 年代较早，默认仿真传感器/控制接口需转换；未针对动态行人。 | **中高，成熟基线**；优先做同场景离线/隔离复现。 |
| [LARICS 多分辨率 3D frontier](https://github.com/larics/uav_frontier_exploration_3d)，2021 | Octree 上不同分辨率检测/聚类 frontier，结构相对直观，适合验证从二维到三维的最小路线。 | 较老的 ROS 工程（提供 Bionic Dockerfile）；地图和机体运动接口需改；无现成动态行人处理。 | **中，适合抽取三维 frontier 思路**。 |
| [FC-Vision](https://github.com/FC-Family/FC-Vision)，RA-L 2026 | 关注未知场景中目标结构被遮挡时的可见性与在线重规划；适合货架侧面和遮挡区域补扫。ROS Noetic。 | 任务是**目标结构扫描**，不是通用未知空间全覆盖；示例依赖 UE4/AirSim；PolyForm Noncommercial，代码使用须遵守许可证。 | **中（补扫阶段），低（作为首个全域探索器）**。 |
| [HERE](https://github.com/Taekbum/here_planner)，RA-L 2026 | 通过辐射场/隐式几何的不确定度选视点，启发“未观测体积 + 表面重建质量”的联合收益；有重建完整度、精度、不确定度评估。 | 作者代码用 Habitat、Gibson/Matterport3D、相机/神经重建软件栈；与 MID-360+ROS1/PX4 接口差异大。仓库 README 不构成真实无人机飞行验证。 | **低（直接部署），高（学术设计启发）**。 |
| [TUM OctoMap + frontier + RRT*](https://github.com/CNLINTUM/uav-exploration-rrt-frontier)，2024 | 三维 OctoMap、frontier、RRT* 的端到端参考，ROS Noetic，易看懂接口划分。 | 学生项目、体量和验证范围有限；以深度相机/Unity 为例，MID-360 与 PX4 需另接。 | **中（快速原型），低（直接作为最终系统）**。 |

以上优缺点是基于作者论文/README与本项目架构推导的集成风险，**不是这些方法在半仓库上的排名或耗时结果**。作者报告的性能不能直接迁移到本项目。

## 建议的实施顺序与验收

1. **先补三维地图证据层。** 用时间同步的 LiDAR 原始/配准扫描、传感器原点和有效射线更新未知/自由/占据体素；记录观测次数/角度/距离或表面质量。FAST-LIO 的全局稠密地图可用于展示，但不能仅从有点的位置推断整个自由空间。动态行人点保持独立时效与过滤策略。
2. **小范围改动现有任务链。** 在半仓库先做 2–3 个允许高度层或完整 `(x,y,z)` frontier；候选收益可由未观测体积、货架表面质量缺口、路径时间、返航余量构成。轨迹必须检查机身扫掠空间、货架顶部/横梁/天花板与动态障碍；只让一个控制器发布实际飞行指令。
3. **做隔离对照。** SHIELD 优先，FALCON 与 FUEL 次之；先复现其自带示例，再用相同世界、初始点、传感器可见性和动态行人条件接统一适配器。记录仿真时间与墙钟时间、飞行距离、CPU/RAM、重规划耗时、碰撞、返航成功率；分开报告未知空间覆盖和参考模型表面完整率/精度。至少重复多次，不把货架侧面支持率当成全三维完整率。

当前结论：要尽快获得**真正三维自主探索**且尽量沿用已有 LiDAR/ROS1 链路，先验证 SHIELD 的观测质量三维占据图与 frontier；要有强论文对照，再单独复现 FALCON；若目标是改善货架遮挡面，再吸收 FC-Vision/HERE 的视点质量思想。此处仍是方案与源码/公开资料核查，未编译或运行这些外部仓库。
