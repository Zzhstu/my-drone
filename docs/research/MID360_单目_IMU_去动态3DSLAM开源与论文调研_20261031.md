# MID360＋单目相机＋IMU：去动态 3D SLAM 开源与论文调研

检索日期：2026-10-31（Asia/Shanghai）。面向用户明确提供的 MID360、单目相机、IMU；不要求额外深度相机。本轮属于文献、仓库与关键接口核查，没有安装、编译、重放或实飞。以下是经过筛选的代表性工作，不是穷尽性综述或算法性能排名。

## 选型结论

如果要测试新的动态感知定位前端，优先 **BTSA**；如果保留现有 FAST-LIO 并增加动态检测，优先 **M-detector**；如果重点是长期静态地图去残影，继续以已接入的 **DUFOMap/FreeDOM** 做基线；需要 TSDF 体积表达时研究 **Dynablox**。

这些方法大多只使用雷达与 IMU，或者注册点云与外部位姿。用户具备相机不意味着每个方法都必须使用相机。相机可用于后续着色或视觉语义融合；这需要额外接口，不能将组合直接写成作者原生支持三传感器的完整系统。

若要求“激光＋单目＋IMU 三者共同估计状态，且动态抑制同时作用于激光和视觉更新”，**Dynamic-LIVO** 是非常贴近的论文，但截至本次核查仍写明接收后公开代码。不能将其当作当前可直接复现的开源选项。可用的工程路线是以 FAST-LIVO2/R3LIVE 为融合基础另接动态机制，但这仍是待验证的集成任务。

## 功能与兼容性对照

| 方法 | 公开代码定位 | 输入 | 动态能力 | MID360 证据与本机边界 |
|---|---|---|---|---|
| BTSA | 动态感知 LIO 前端＋静态建图 | LiDAR＋IMU | 在迭代配准中筛选稳定点，并做空间一致性静态图构建 | 原论文实验明确含 MID360；代码有 Livox raw 分支。不是已验证的本机直接运行；相机不参与，未确认回环模块 |
| M-detector | 动态事件/运动点检测模块 | 局部点云＋对应位姿，通常来自 LIO | 遮挡关系检测运动点，提供动态/静态结果 | 官方有 `config/mid360/mid360.yaml`；默认 Avia launch 不会自动加载此文件。外部位姿、逐点时间/字段、坐标和配对需适配 |
| DUFOMap | 在线/离线动态感知映射与清图引擎 | 点云＋传感器位姿 | 从曾可靠为空的区域检测/排除动态点，生成长期静态背景 | 官方 README 有 MID360 展示；本项目已有 native 引擎适配和双图输出。不是独立里程计/回环系统 |
| FreeDOM | 在线扫描动态过滤＋地图细化 | 点云＋外部位姿/TF | 保守自由空间估计，扫描去动态并清理历史地图残留 | 本项目已有 MID360 旁路适配；射线增强关闭，不能等同原论文完整配置或已证明最优 |
| Dynablox | 基于体积地图的在线动态检测 | 点云＋外部位姿 | TSDF＋时序高可信自由空间识别多类运动物体 | 接口适合研究接入；本轮未确认专用 MID360 默认配置。需验证稀疏采样、薄结构、积分范围和资源 |
| Dynamic-LIO | LIO＋SC-A-LOAM 回环后端 | LiDAR＋IMU | 地面/非地面标签一致性、邻域与未决点再判定 | 公开入口主要是车载数据；不能将 Livox 选项当 MID360 已实测。地面假设及扫描重构需审查，飞行高度/俯仰变化下优先级较低 |
| Removert | 离线地图清理工具 | 逐帧扫描＋位姿 | 多分辨率 range image 比较清图 | 可作离线基线；不能作为独立实时 SLAM。作者 README 明确当前 revert 步骤未完整包含 |
| ERASOR | 离线静态地图构建/更新 | 累积地图＋逐帧扫描/位姿 | 伪占据比例与区域地面恢复 | 车载地面与高度参数明显；MID360/无人机升降需重新验证，不是优先机载方案 |

“影响定位”和“清理地图”不同。以 FAST-LIO 输出位姿后运行一个检测器，不会自动消除该帧已经受到的动态匹配误差；若需保护状态估计，必须把动态证据在适当时机接入配准更新。清理显示/导出的地图也不会自动修改前端内部匹配地图。

## 六篇优先阅读论文与实际开放范围

### 1. BTSA：优先研究动态感知定位

**Breaking the Static Assumption: A Dynamic-Aware LIO Framework Via Spatio-Temporal Normal Analysis**，Zhiqiang Chen 等，IEEE Robotics and Automation Letters，2025。

- [论文](https://arxiv.org/abs/2510.22313)；[作者代码](https://github.com/thisparticle/btsa)。
- 将点放在四维时空中估计法向，在迭代配准时选取稳定点，联合处理状态估计与动态识别，另用空间一致性维护静态地图。
- 原文 V-A2 明确数据包含 Livox Mid-360；不是仅以“支持 Livox”推测兼容。
- 源码 `config/dynamic.yaml` 使用 `/livox/lidar`、`/livox/imu` 和 `lidar_type: 4`；`src/preprocess.h` 将 4 定义为 `LIVOXRAW`；`src/preprocess.cpp::livoxraw_handler` 消费 PointCloud2 的 `offset_time`，除以 1e6 转成毫秒。与本机 driver2 CustomMsg 等实际输入仍可能需要转换。
- 主要边界：法向估计受点密度和时空分布影响。原文把新观测、不可可靠估计的点也归为不稳定，不能把所有排除点解释为真实动态。V-B 明确报告稀疏条件下误删/漏检取舍；不能据此宣称完全解决 MID360 非重复扫描。
- 本轮阅读：方法 III/IV、MID360 实验段与静态图局限、README/配置/预处理关键段。未复现性能，未确认完整回环链。

### 2. M-detector：优先研究与现有 FAST-LIO 接口结合

**Moving event detection from LiDAR point streams**，Huajie Wu、Yihang Li、Wei Xu、Fanze Kong、Fu Zhang，Nature Communications 15, 345，2024。DOI：10.1038/s41467-023-44554-8。

- [论文](https://www.nature.com/articles/s41467-023-44554-8)；[作者代码](https://github.com/hku-mars/M-detector)。注意正式标题与 README 中的简写不完全相同，以出版页为准。
- 利用遮挡原则检测运动点，无需预设人/车类别。论文展示无人机应用，但其 UAV 实验雷达为 Avia，不是本项目 MID360 实飞证据。
- MID360 具体证据：官方参数文件 `config/mid360/mid360.yaml`，而非只有 Avia 支持声明。
- `src/dynfilter_with_odom.cpp` 订阅点云与里程计，发布 `/m_detector/point_out`、`/m_detector/frame_out`、`/m_detector/std_points`。其默认队列配对和本项目时间戳必须核对，不能只改话题名便保证同步。
- 论文点级微秒检测延迟不能直接当 ROS 全链、整帧或本机延迟；历史地图中已写入的鬼影也仍需维护策略。
- 本轮阅读：出版页摘要、原理、相关 UAV/建图应用段，README、MID360 配置和 ROS 接口源码。未编译/实测。

### 3. DUFOMap：优先作为已有静态背景基线

**DUFOMap: Efficient Dynamic Awareness Mapping**，Daniel Duberg、Qingwen Zhang、Mingkai Jia、Patric Jensfelt，IEEE RA-L 9(6):5038–5045，2024。DOI：10.1109/LRA.2024.3387658。

- [论文](https://arxiv.org/abs/2403.01449)；[作者代码](https://github.com/KTH-RPL/dufomap)；[作者项目页](https://kth-rpl.github.io/dufomap/)。
- 用射线建立可靠历史空区域，落入这些区域的回波作为动态证据。支持在线动态检测及离线图清理；不负责输出自身的激光惯性里程计。
- 官方 README 明确列 Livox MID360 并展示两层楼采集结果。
- 本项目 `dufomap_adapter.py` 已订阅注册扫描、位姿与同帧 ACK，维护独立 native 引擎、发布静态图。已有仿真报告存在；本轮没有重新运行，不能说本轮完成新复现。
- 目标边界：历史背景地图可以排除已经停止的暂态物体，而避障需要保留当前真实占据；不能用“DUFO 无点”判定空间可飞。原接入的非零回环历史一致重建缺口仍在。
- 本轮阅读：原论文方法定义、作者 README，复核本地适配器与既有报告。未作作者数据集完整复现。

### 4. FreeDOM：扫描过滤和旧残影细化都关注

**FreeDOM: Online Dynamic Object Removal Framework for Static Map Construction Based on Conservative Free Space Estimation**，Chen Li、Wanlei Li、Wenhao Liu、Yixiang Shu、Yunjiang Lou，IEEE RA-L 10(6):5577–5584，2025。DOI：10.1109/LRA.2025.3560881。

- [论文](https://arxiv.org/abs/2504.11073)；[作者代码](https://github.com/LC-Robotics/FreeDOM)。
- 多分辨率地图、保守自由空间估计、scan-removal 前端和 map-refinement 后端，较适合关注“先静止后移动留下鬼影”的地图维护任务。
- 本项目已存在独立 `astra_mid360_baseline.launch`，消费去畸变 body 点云与 `camera_init→body` TF，输出独立静态图；不接管原规划/前端匹配地图。
- 当前适配关闭 raycast enhancement，因为缺经核验的 MID360 FOV 掩膜；不把非重复扫描未观测方向假设为空，也不把此配置叫完整论文复现。
- 本轮阅读：论文问题定义/前端/后端框架、作者 README 和本地配置。没有新增算法效果实验。

### 5. Dynablox：体积地图与动态检测结合

**Dynablox: Real-time Detection of Diverse Dynamic Objects in Complex Environments**，Lukas Schmid、Olov Andersson、Aurelio Sulser、Patrick Pfreundschuh、Roland Siegwart，IEEE RA-L 8(10):6259–6266，2023。DOI：10.1109/LRA.2023.3305239。

- [论文](https://arxiv.org/abs/2304.10049)；[作者代码](https://github.com/ethz-asl/dynablox)。
- 扩展 Voxblox 的 TSDF，结合占据持续时间和高可信自由空间检测动态点，不限于网络训练过的人/车类别。作者数据用 FAST-LIO2 得到外部状态估计。
- 适合研究动态检测、体积地图和表面重建的结合；但默认输出不能直接等同“已经清干净的彩色纹理模型”，静态融合、表面更新与颜色仍需适配。
- 官方开发环境 Ubuntu20.04/ROS Noetic；当前本轮未确认专用 MID360 配置，不能写原生直接支持。论文局限含薄/稀疏表面、反光和强遮挡。
- 本轮阅读：原文 III/IV、实验配置与局限、作者 README。未接入本机。

### 6. Dynamic-LIO：有完整前后端入口，但优先考虑车载假设

**LiDAR-Inertial Odometry in Dynamic Driving Scenarios using Label Consistency Detection**，Zikang Yuan、Xiaoxiang Wang、Jingying Wu、Junda Cheng、Xin Yang；2024 arXiv 版本，作者仓库标注 IROS2025。

- [论文](https://arxiv.org/abs/2407.03590)；[作者代码](https://github.com/ZikangYuan/dynamic_lio)。
- 基于地面/非地面标签一致性、邻域关联和未决点再判定，前端基于 SR-LIO，后端使用 SC-A-LOAM。
- 原文场景假设明确偏道路：动态物体位于地面。对飞行平台、多高度观测、非重复扫描的 sweep 重构需要核验。
- 本轮读取的 `sr_lio/config/ulhk_CA.yaml` 为 Robosense 数据配置，包含时间单位字段；不能据泛称 Livox 支持就宣称 MID360 已适配。
- 本轮阅读：论文方法与系统概览、作者 README/代表配置；未将作者耗时或精度数字移用到本项目。

## 两个离线基线

1. **Remove, then Revert: Static Point cloud Map Construction using Multiresolution Range Images**，Giseop Kim、Ayoung Kim，IROS2020。[论文](https://gisbi-kim.github.io/publications/gkim-2020-iros.pdf)；[代码](https://github.com/gisbi-kim/removert)。需要逐帧扫描及对应位姿；官方 README 明确当前程序离线运行，且 future 列表写了 revert steps 当前省略。不能因论文名称就声称仓库完整复现其全部机制。MID360 range image 的稀疏/非规则采样需处理。
2. **ERASOR: Egocentric Ratio of Pseudo Occupancy-Based Dynamic Object Removal for Static 3D Point Cloud Map Building**，Hyungtae Lim、Sungwon Hwang、Hyun Myung，IEEE RA-L2021。[论文](https://arxiv.org/abs/2103.04316)；[代码](https://github.com/LimHyungTae/ERASOR)。可清理累计地图，已有逐帧 PCD＋位姿的自定义输入说明；地面/高度和坐标系约定对无人机升降/倾斜较敏感。不是在线估计状态的完整替代。

阅读范围：以上离线方法以作者 README、论文摘要/来源页为主，未进行方法全文复现或运行。其存在不意味着比在线方法更适合机载。

## 同时使用激光、相机和 IMU 的相关论文：开放状态单独列出

- **Dynamic-LIVO: A Dynamic-Aware LiDAR-Inertial-Visual Odometry System Using Spatio-Temporal Normals**，Zhixin Zhang 等，arXiv:2609.19336，2026-09-16。[论文](https://arxiv.org/abs/2609.19336)。将时空法向动态分类传递给 LIO 和 VIO；为新区域/稀疏点增加延迟判定，生成静态彩色图。原文实验确有 MID360＋视觉数据，也有 Ouster＋普通 Logitech C920 单目采集平台；不要求深度相机输出深度。**原文仍写代码与自采数据将在接收后发布，本轮未找到并核验完整作者代码，暂列论文跟踪。** 阅读摘要、方法框架、传感器配置及开放说明，不引用其性能数字为本项目收益。
- **Dynam-LVIO: A Dynamic-Object-Aware LiDAR Visual Inertial Odometry in Dynamic Urban Environments**，IEEE Transactions on Instrumentation and Measurement 73，2024，DOI：10.1109/TIM.2024.3395320。[论文](https://ieeexplore.ieee.org/document/10511062/)。官方摘要包含 YOLOv5、LVI-SORT、环境/物体分图；本轮未确认作者完整开源代码或 MID360 即用配置，不放入已确认开源主清单。阅读范围为出版页摘要。

没有检索到可核验的代码不等于绝对不存在。发布状态会变，部署前应重新检查。不要将名称类似的其他 Dynamic-LIO/LIVO 仓库当作这些论文的实现。

## 相机在建议系统中如何发挥作用

拟议链路一：保持现有 FAST-LIO／动态地图维护，加入 M-detector 做同输入检测对照，再将同步相机图像用于**确认静态且可见的表面**着色。这样不用深度相机，但着色模块与遮挡/动态图像掩膜仍待实现。

拟议链路二：若动态物体确实影响定位，隔离运行 BTSA 与当前 FAST-LIO，比较同原始雷达/IMU下的定位和静态图质量。BTSA 不是已实现的三传感器融合；需要时后续再研究融合视觉约束。

拟议链路三：确需视觉参与状态估计时，以 [FAST-LIVO2](https://github.com/hku-mars/FAST-LIVO2)／[R3LIVE](https://github.com/hku-mars/r3live) 为基础加入动态检测和地图维护；[作者 LIV-Eye 工程](https://github.com/hku-mars/LIV_handhold_2) 已提供 FAST-LIVO2 的 MID360 配置及同步硬件参考。它们本身不能冒充已具备专用动态清理。后置清图不能保护已经使用动态视觉 patch 的状态更新，要同时检查 LIO/VIO 观测筛选与地图更新时机。

单目通常只覆盖雷达360°视场的一部分，语义掩膜不能自动覆盖机后雷达点。相机中“人/车类别”与物体当前是否运动也不同；长期静态背景可以剔除暂态对象，但导航必须保留当前障碍。

## 最小验证安排（建议，尚未执行）

保留同步单目图、相机参数、MID360 原始点云/逐点时间、IMU与各外参/时间偏差。至少比较全静态自运动、行人持续移动、先静后动、动后停止、薄杆/墙角/反光和回访遮挡六类输入。先固定原始输入对照，再决定新闭环导航实验。

分别报告：定位 ATE/RPE、动态点识别/残留、静态误删/薄结构保留、清理延迟、实际观测表面完整性、峰值内存和端到端时延/积压。独立真值只用于评估；各论文异机耗时不能当本机/Orin指标，地图干净也不证明定位更准、零鬼影、完整三维或飞行安全。新组件先以旁路输出验证，不能直接改飞控来源。
