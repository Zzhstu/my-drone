# SLAM2 数据采集清单：AstraDroneOpen

核查日期：2026-10-31（Asia/Shanghai）。这是采集与转换方案，尚未实施录制、导出、模型推理或 SLAM2 运行。

**本日后续澄清：SLAM2 的 RGB-D 入口要求深度信息，不限定必须使用深度相机。** 下文原先以 D435i 为具体采集示例；单目相机＋MID360＋IMU 也可作为传感器方案，但需要把同步、去畸变的雷达点投影为相机坐标深度图，并针对稀疏深度验证/适配。此方案尚未实施或运行通过，不能直接当作原 RGB-D 配置的等价替换。

用户链接 `https://github.com/SEAL-UofG/SLAM2` 当前跳转至 `AIR-Lan/SLAM2`。本轮核查版本为 `877f9e10902067b232eda767b4c31b1c39e28dab`。核查 README、RGB-D 入口、配置、System/Tracking/平面映射、YOLO 加载和关联脚本，未编译或复现论文。

## 需要收集什么

SLAM2 的 RGB-D 主入口直接读取：**彩色图 + 注册到彩色相机像素坐标的深度图 + 平面实例分割图 + 三者的时间关联 + 相机参数**。这是视觉 RGB-D 方法，不直接消费我们导出的 FAST-LIO/DUFO 静态 PCD。

| 数据 | 如何获得 | 用途与要求 |
|---|---|---|
| 彩色图 | 单目彩色相机或 D435i 彩色相机原始 Image | 必采；保留原采集时间、编码、分辨率，离线导出无损 PNG |
| 原始深度信息 | RGB-D 路线采深度 Image；单目＋雷达路线采 MID360 原始点云及逐点时间、IMU | 需要有可构造度量深度的测量；保留原始编码、单位、无效值，不录伪彩显示图代替数值深度 |
| 相机像素坐标深度图 | RGB-D 深度配准，或雷达去畸变/同步后投影 | 实际送入 SLAM2；像素必须与彩色图对应；雷达投影存在稀疏与遮挡差异，需验证适配 |
| 相机内参/CameraInfo | 单目路线保存彩色相机参数；RGB-D 路线另存深度相机参数 | 保存 K/D/R/P、分辨率、frame_id 与变化；转换为本相机 YAML |
| 相机外参 | 仿真 SDF 完整变换链；真机标定 | 按路线保存 depth→color 或 LiDAR/IMU→camera，以及 body→color optical；配准、跨方法对齐和相机真值需要 |
| 平面实例 mask | 对每张 RGB 使用 PlaneRecNet 等离线推理后转换 | 派生数据，不需要传感器现场直接输出；不等于人/非人二值 mask |
| 三路关联表 | 从原始图像时间戳和 mask 对应 RGB 生成 | 六字段，顺序为 RGB 时间/路径、深度时间/路径、mask 时间/路径 |
| 相机轨迹真值 | 仿真 world→body 加 body→camera optical；真机独立动捕等 | 评估定位需要，RGB-D 算法入口不要求；FAST-LIO/MAVROS 估计不能当独立真值 |
| 原始 LiDAR、原始 IMU | `/livox/lidar`、`/livox/imu` | RGB-D 入口不使用，但为本项目同航次 FAST-LIO/R3LIVE 对照应保留 |
| 估计位姿、注册扫描、TF、时钟 | 现有工程话题 | 支持重放、对齐与审计；它们不能代替 RGB-D 原始数据 |
| 动态物体真值/静态参考 | 仿真人物位姿、静态几何；有条件增加像素/点级真实标签 | 评估鬼影、静态误删、重建完整性；人物位置不等于逐像素动态真值 |

模型权重、COCO 类别表、ORB/线词典是另外的运行资源，不是飞行中采集的数据。先用预训练模型推理，无须为了运行 SLAM2 就从头采集大规模训练标签。若研究仿真域适配，则另建不混入评估集的训练/验证序列。

## 单目相机＋MID360 的替代路线

这套传感器可以做激光惯性视觉建图，不要求额外购买深度相机。若目标是 SLAM2，拟采用的适配流程为：

1. 采集同步彩色图、MID360 原始点云及逐点时间、IMU，相机内参/畸变以及雷达—IMU—相机外参/时间偏差。现有 `/livox/imu` 是本项目激光惯性链路输入，不能漏录。
2. 利用位姿与 IMU 对扫描去畸变，并把各回波变换到图像曝光时刻的相机光学坐标：`p_C = (X_C,Y_C,Z_C)`；按相机模型投影到图像，只保留 `Z_C>0` 且落在视野中的点。深度值用 `Z_C`，不能直接把雷达到点的欧氏距离填入像素。
3. 对落入同一像素的回波进行最近深度选择，并处理相机/雷达视差和前景遮挡；无观测像素保持无效。RGB、深度和 mask 的畸变处理与像素坐标要一致。
4. 再将投影深度、RGB、平面实例 mask 及关联表送入 SLAM2。现入口不直接读取 MID360 点云。

原代码 `Frame::ComputeStereoFromRGBD` 在 ORB 关键点的精确像素位置读取深度，仅在深度大于 0 时赋值；线段三维恢复还要求端点有有效深度。因此稀疏投影图即使能被文件接口读取，也可能给不到足够的特征深度。是否要改为局部可靠深度关联、静态平面支持或经过验证的深度补全，需要新实验决定；不能随意插值跨过人体边缘、墙角和遮挡来填满。

MID360 非重复扫描可通过多帧获得更多静态表面采样，但跨帧须做运动补偿、动态排除和可见性检查，运动人体不可直接叠加；不能借助未来全局地图生成深度却仍声称原版在线 RGB-D 实验。使用 FAST-LIO 位姿辅助时也应明确是增加激光惯性信息的适配系统。

若目的是用现有硬件做彩色三维建图，而不是专门复现 SLAM2，可优先考虑本来面向 LiDAR＋IMU＋相机的 [R3LIVE](https://github.com/hku-mars/r3live) 或 [FAST-LIVO2](https://github.com/hku-mars/FAST-LIVO2)。MID360 消息/时间字段及本机标定仍须适配验证，动态清理仍需单独集成，尚无本项目运行证据。

## 当前工程的实际缺口

1. `iris_mid360.sdf` 已挂载 D435i；`simulation/astra_gazebo_models/D435i/model.sdf` 配置彩色/深度 Image 和 CameraInfo，均为 640×480，插件更新率配置 30 Hz。这仅为源码配置，未在本轮启动核实发布、实际帧率或加载库版本。
2. 彩色相机 `horizontal_fov=1.211`，深度相机为 `1.571`。尺寸相同但内参不同，不能直接逐像素使用。应使用各自内参与外参做重投影/遮挡处理，得到彩色坐标的深度；这不是简单缩放图像。相机变换链要读完整 SDF，不能只用机体上的安装平移。
3. `RealSensePlugin.cpp` 定义 `DEPTH_SCALE_M=0.001`，`gazebo_ros_realsense.cpp` 发布 `16UC1`，因此按当前源码深度为毫米。若保持毫米 PNG，应设置 `DepthMapFactor: 1000.0`；若导出为 TUM 的 5000 倍编码，必须实际重编码后再设置 5000.0。1 m 应分别对应 1000 或 5000，不要仅改 YAML 冒充重编码。无效深度保留 0。
4. `experiment_evidence.py` 的 `EVIDENCE_TOPICS` 没有相机 Image/CameraInfo。现有 full 与 compact 录包均不能仅靠切档获得 RGB-D。compact 还主动省略原始 `/livox/lidar` 和 `/livox/imu`。应另建明确的采集清单，不能把 compact 的地图重放能力当完整多传感器数据集。
5. 复核 `office50_dual_map_runs/office50_dual_map_20261030_184237_evidence_recording.json`，话题清单不包含相机流；该包不能直接用于 SLAM2。已有世界、航线和人物运动设计可复用，图像须重新采集。

相机 SDF 配置的相对话题名为 `color/image_raw`、`depth/image_raw`、`color/camera_info`、`depth/camera_info`。最终完整 ROS 话题名须在启动后核实 namespace，不假定一定带 `/camera/` 前缀。红外图不是此 RGB-D 入口的必要输入。

## mask 的实际编码

`src/planar_mapping_module.cc:215–225` 使用 `cv::Vec3b` 读取 mask，以三个颜色字节编码分组，并跳过全黑背景。兼容导出应满足：

- 8 位三通道 PNG；同一个平面实例内部保持同一种非黑颜色，不同平面实例用不同颜色；背景为黑色。
- 与送入的 RGB/深度处于同一分辨率、像素坐标与畸变处理约定。实例标签缩放用最近邻，避免制造混合颜色；保留原始预测及转换参数。
- PlaneRecNet 默认 `simple_inference.py` 输出将 mask 半透明叠加到原图的展示图，还可能画框和文字。这种展示图每个像素颜色受纹理影响，不能直接充当 SLAM2 平面标签图。须从原始 `pred_masks` 导出纯色实例图。
- PlaneRecNet 预测的平面 mask 是算法输入，不是动态分割评估真值。它的单目预测深度也不应未经尺度验证便替代实际测量深度。

## 建议保存结构

```text
sequence_01/
  raw.bag
  rgb/
  depth_raw/
  depth/                 # 已注册到 RGB、注明编码单位
  mask/                  # 与 RGB 对应的纯色平面实例图
  rgb.txt
  depth.txt
  mask.txt
  associations.txt
  camera.yaml
  calibration.yaml
  groundtruth.txt        # 评估可选：world→color optical
  manifest.json          # 源包、时间约定、编码、配准/模型版本、文件 SHA
```

`associations.txt` 每行例如以下六字段，文件只放有效数据行；当前加载器没有跳过 `#` 注释的逻辑：

```text
100.000000 rgb/100.000000.png 100.002000 depth/100.002000.png 100.000000 mask/100.000000.png
```

mask 时间戳为其来源 RGB 的时间戳，不是离线推理完成时间。仿真使用统一 `/clock` 的秒数即可，不要与系统墙钟混用。保留原始深度时间和实际配对误差，按时间匹配而不是只按帧编号。当前入口仅把 RGB 时间送入跟踪，不会自动拒绝 RGB/深度的错误配对，导出阶段必须检查。

建议从 640×480、30 Hz 采集配置开始，先录 30–60 秒做数据链检查。这是面向当前仿真的建议，不是算法固定最低规格或已经测得的实际帧率。RGB/深度时间差可先以不超过 10 ms 为采集目标，并报告实际分布；阈值需结合运动速度验证。RGB 的读取顺序通常是 OpenCV BGR，`Camera.RGB` 应按实际加载的通道顺序填写；相机内参与深度比例不要照抄 TUM/Bonn 示例。

## 最小采集场景与评价

先同场景、尽量相同传感器轨迹分别录制：

1. 无行人静态序列：墙、地面、桌椅/货架清楚可见，验证位姿、尺度和平面。
2. 行人持续移动：横穿相机视野，保证静态背景仍有可见区域。
3. 行人先静止再移动：验证已入图人体能否清理。
4. 行人移动后停止：验证长期背景与当前真实障碍的区别。
5. 闭合回访：从不同方向重看此前被遮挡区域，检验残影及重建。

上述为建议的机制检查，不是已完成实验或统计充分的基准。后续再增加重复、纹理/照明/动态比例/速度变化。仿真人物与相机画面是否被预训练检测器识别需单独检查，不把仿真外观逼真当跨域性能通过。

比较 SLAM2 和现有激光方案时，共用同航次原始数据与独立真值。输入模态不同应明确报告；先固定传感器轨迹离线比较建图，再新做闭环比较导航。建议报告 ATE/RPE、动态残留、静态误删、几何误差/实际观测表面完整性、跟踪失败、处理时延与资源；不能用好看的地图或人物中心距离代替逐点/逐像素真值。原机载安全/控制不由尚未验证的 SLAM2 输出接管。

## 运行资源及入口注意

仓库 RGB-D 实际入口需要两个词典：

```bash
./Examples/RGB-D/rgbd_tum ORBvoc.txt LSvoc.txt camera.yaml sequence_01 sequence_01/associations.txt
```

这是源码参数顺序说明，未在本机执行；路径需替换为实际文件。`rgbd_tum.cc` 判断 `argc==6`，使用 argv[1]/[2] 为 ORB/线词典，argv[3] 为 YAML，argv[4] 为序列根目录，argv[5] 为六字段关联文件；其 Usage 文本没有完整反映这些参数。普通 TUM 的四字段 RGB/深度关联文件还需加入 mask。

`src/YOLOV5.cc` 的模型和 `coco.names` 路径硬编码在作者目录，并选择 CUDA，不能以为只准备数据即可运行。当前仓库树未列出这些权重。`Examples/ROS/.../ros_rgbd.cc` 仍以无 mask 的旧接口调用 `TrackRGBD`，与当前头文件要求不一致；不要据此宣称在线三路 ROS 入口已可用。应先验证离线 RGB-D 完整输入，再适配 ROS。
