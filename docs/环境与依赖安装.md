## 一键安装常用 apt 依赖

### 前提

1. 使用 Ubuntu 20.04 amd64，确保 Ubuntu 软件源与 ROS Noetic 软件源已经配置且可访问，并有 sudo 权限。ROS 安装和软件源配置参考 [ROS Noetic 官方安装说明](http://wiki.ros.org/noetic/Installation/Ubuntu)。脚本不会修改软件源或信任密钥。
2. 有网络与足够磁盘空间。安装过程中会更新 apt 索引并通过系统包管理器安装/升级所列依赖，不执行全系统 upgrade 或 dist-upgrade。
3. 先在克隆目录查看并模拟：

```bash
cd ~/my-drone                         # 替换为实际克隆目录
bash scripts/install_dependencies.sh --help
bash scripts/install_dependencies.sh --check
```

模拟通过后执行：

```bash
bash scripts/install_dependencies.sh
```

可选地在安装常用 apt 依赖时配置 DUFOMap：

```bash
bash scripts/install_dependencies.sh --dufomap
```

脚本安装 ROS Noetic 桌面版、MAVROS、Gazebo Classic、catkin 工具，以及 PCL、OpenCV、Eigen、Ceres、Python 数值库等常用包。包清单以 `scripts/install_dependencies.sh` 的 `PACKAGES` 为准；它不锁定 apt 的每个小版本。若 `.venvs/dufomap` 已存在，`--dufomap` 只检查版本，不覆盖该环境；新建时调用现有安装脚本并校验导入。

如果 `--check` 提示找不到 ROS 包，先配置可访问的 ROS Noetic 源并更新软件索引，再检查；如果某一依赖无法解析或网络失败，安装会停止，不能把部分安装当作完成。脚本本身不自动安装或编译整个项目。

## 仍需单独配置的组件

- **PX4 v1.15.4**：按 [PX4 v1.15 Ubuntu 开发环境](https://docs.px4.io/v1.15/en/dev_setup/dev_env_linux_ubuntu)准备源码、子模块、依赖并编译 SITL。旧版 `scripts/env_sh/01_env_px4_init_pc.sh` 会清理已有 PX4 构建目录，并修改 shell 环境；先阅读脚本，不建议在有数据的现有环境直接执行。项目还依赖本机曾修改的 Gazebo 子模块和 launch，具体差异尚待完整整理。
- **ROS 工作空间**：本仓库不带 `build/`、`devel/`。需要先配置所需第三方包和依赖，再分别构建 `simulation/sim_workspace` 和 `AstraDrone_ros1_ws`；仓库中存在指向 `/opt/ros/noetic` 的 catkin 顶层符号链接，其他本机路径也需检查。未提供已经在干净机器验证的统一构建命令。
- **PedSim / 雷达插件**：部分入口引用 `/home/a/pedsim_ws`，需要相应源码、插件和已编译环境，并根据实际路径调整。MID360 Gazebo 插件也需要按工作空间与对应 PX4/Gazebo 环境构建。
- **MAVROS 地理数据**：检查目标机所需 GeographicLib 数据及 MAVROS 配置；项目内 `third_party/GeographicLib` 有部分资源，但本脚本不会覆盖 `/usr/share`。
- **DUFOMap 双图**：`--dufomap` 只配置独立 Python 依赖，还需要 ROS 工作空间、相关地图节点及其运行条件。
- **3DGS 与 GPU**：按 [LiDAR/gsplat 说明](LIO_GSPLAT_CN.md) 和 `scripts/run_sh/build_roomgs_demo.sh` 检查 NVIDIA 驱动、CUDA、Python、PyTorch 和 gsplat。现有构建脚本有固定源码版本、下载及构建动作，在已有环境执行前先阅读；本一键 apt 脚本不会执行它。航线、权重和已训练模型未随仓库发布。

当前一键脚本仅做了 shell 语法、静态检查和本机 apt 安装模拟，**未在全新 Ubuntu 环境执行实际安装，也未由此完成工作空间编译或 SITL 飞行**。如要确认特定目标机可以运行，应逐项核实缺失依赖、构建和启动结果。
