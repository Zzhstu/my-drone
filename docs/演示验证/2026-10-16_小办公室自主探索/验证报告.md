```bash
cd /home/a/AstraDroneOpen
bash scripts/run_sh/small_indoor_exploration_demo.sh
```

默认打开Gazebo与RViz，自动起飞至相对1.2m、自主选点、补扫、返航驻留、保存并退出。`--keep-open`在成功返航后保留窗口；`--headless`关闭两种GUI。首次构建与操作见[完整说明](../../../AstraDrone_ros1_ws/src/SLAM/fastlio_bridge/SMALL_INDOOR_DEMO_CN.md)。本轮为静态室内，无行人、语义网络或回环；探索器不接收world平面图或Gazebo真值。

## 本次解决的接口问题

首轮真实飞行暴露PX4解锁时航向重新对齐：固定的map轴与后来的PX4局部轴相差约90度。只等待航向稳定不足以解决解锁重对齐，第二轮还发现本环境未解锁system_status一直为0，不能依赖STANDBY判定。负结果保持，未记成成功。

新demo增加有界地面航向等待，以及独立`small_indoor_velocity.py`：使用新鲜、近时配对的map和MAVROS机体姿态，将地图XY速度旋转到局部ENU，Z保持；失效输出零速度。本轮约-90度偏航差实际存在且被转换，在线确认向飞控速度话题发布的节点只有该转换器。转换仅针对两种重力对齐坐标系的偏航，不是完整三维坐标复位补偿；未做飞行中断流故障注入。旧桥、控制器、风险和探索器源码保持。
