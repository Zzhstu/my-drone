# 实机单目＋MID360/内置IMU：采集后主机离线3DGS流程

2026-11-04。用户确认机载系统与当前主机相同；本机实际核验为Ubuntu20.04.6、ROS Noetic。本文是部署流程和接口核验，尚未连接实机、标定或进行实飞。

## 任务分工

无人机：真实传感器驱动、FAST-LIO定位（机载资源允许时）、有界数据记录。飞控继续承担飞行控制。

主机：检查录包、必要时离线重跑FAST-LIO、导出静态点云和逐图位姿、离线gsplat、原生查看。无需把训练环境和CUDA工具链装到无人机上。只有记录需求时可先机载录原始数据，回主机再估计轨迹；机载定位是否同时供飞控使用是另一个待验证接口。

流程：传感器固定与驱动→内外参标定/时钟对齐→地面短录包验证→实景低速采集→主机数据导出与质量检查→gsplat训练→原图/渲染对照和原生查看。

## 1. 驱动和消息接口

MID360用Livox SDK2/ROS Driver2，相机用对应ROS驱动；检查实际点云、IMU、RGB和CameraInfo消息。官方驱动支持MID360与ROS Noetic：[Livox ROS Driver2](https://github.com/Livox-SDK/livox_ros_driver2)。

当前工程的FAST-LIO源码使用`livox_ros_driver/CustomMsg`，而Driver2常见输出为`livox_ros_driver2/CustomMsg`；必须核对实际`rostopic type`与消息定义并统一接口，保留逐点offset_time/强度/线号等预处理所需字段。只改话题名不视为适配完成。当前`mapping_mid360.launch`有`sim_lidar`分支，实机不能启用模拟点云处理。

## 2. 标定与时钟

- 相机K/D：实际镜头、焦距、分辨率下的内参与畸变，确定针孔/鱼眼模型。固定焦距和安装后再标定；导出去畸变图时同步更新有效K/尺寸。当前训练加载器拒绝非零D，不能把真实畸变参数直接写成0。
- LiDAR/IMU：核对内置IMU的厂家坐标约定、外参和本地FAST-LIO参数，不能凭“内置”就默认所有变换为单位阵。当前YAML的值不是本轮重新标定的实机证据。
- 相机/LiDAR或相机/IMU：真实安装的完整6DoF外参，包含光学轴约定。Gazebo SDF只能说明仿真安装，不能直接当实机标定结果。
- 时间：RGB曝光采集时间、LiDAR/IMU和LIO状态必须映射到同一时间基准，测量固定偏差与漂移。MID360支持PTP等方式，但雷达已同步并不自动保证相机也同步，仍需核验相机时间戳。[MID360官方同步说明](https://livox-wiki-en.readthedocs.io/en/latest/tutorials/new_product/mid360/mid360.html#supported-time-synchronization-methods)

本地Driver2含NoSync时间映射扩展；其单调性不等于与相机曝光时钟已标定。FAST-LIO的`time_sync_en`不是相机-雷达硬件同步开关。

若T_A_B表示从B到A，逐图位姿按实际标定计算：

`T_map_camera(t_rgb) = T_map_imu(t_rgb) × T_imu_camera`

中间可通过LiDAR连接外参，但必须核对正逆方向。当前PoseBuffer可按RGB时间括区插值LIO状态；它只解决时间采样，不替代时间偏差标定或视觉位姿优化。RGB与点云不需要一帧对一帧，也不要求每个像素有实测深度。

## 3. 地面验证

先不依赖自主飞行，录一段短数据：静止初始化、缓慢平移和转动、重看同一墙角/物体。验证时间戳递增、点内时间有效、相机曝光与清晰度、无明显掉帧、LIO墙面重合，以及点云投影与图像轮廓匹配。地面数据能在主机完整重建后，再扩大真实飞行采集。

检查采集和落盘负载后再确定速率与SSD预算。原始IMU/去畸变所需LiDAR时间信息保留；RGB关键帧数量可以控制，不能靠随意丢IMU和点时间降流。建议先保留原始传感器包和一种高质量图像记录，避免同一图像重复保存多份。

## 4. 实际场景采集

先无行人静态场景，低速、平移、多视角、有重叠。首次可以遥控飞行采集；离线重建不要求先实现自主探索。高度按实际屋顶、机体尺寸和飞行条件确定，不能照搬仿真0.65/1.20/1.90m。若只能固定高度，报告上/下层盲区；通过俯仰机构或分次改变固定安装角度补采时，必须记录对应外参/关节角。

每次至少保存：原始LiDAR＋IMU、RGB及采集时间、CameraInfo/标定文件、估计轨迹/帧约定；在线运行LIO时同时记录Odometry。数据落机载SSD，回收后复制校验到主机，流程不依赖持续传输高流量图像到地面站。

## 5. 主机导出与训练

1. 必要时从原始包重跑LIO，生成同一坐标系的实测静态点云和时间轨迹。
2. 去畸变RGB、更新K，按曝光时间计算每张图的c2w；保留原图/时间/外参来源。
3. 检查标定投影、长时漂移、重影、曝光模糊、帧间重叠与采集区域缺口；不合格先修数据或补采。
4. 导出当前后端需要的`static_map.npz/pcd`、`dataset/images/`、`dataset/frames.json`、`camera_input.json`及真实标定/轨迹/验证记录。
5. 沿用主机gsplat环境训练新模型。实景训练的是实景新数据，仿真仓库学习参数不等于实景地图；实际密度、分辨率和步数应按数据量与资源重新验收。
6. 同留出图像/固定视角检查外观与边缘，导出PLY/PT/NPZ，在既有原生窗口查看。

无深度相机要求：深度约束可由标定后的LiDAR稀疏投影产生；它不是逐像素完整深度测量。动态场景日后再加已存在的图像Mask/动态点处理，先打通静态实机链。

## 当前仍需实机适配的代码边界

| 部件 | 当前事实 | 实机工作 |
|---|---|---|
| `integration/half_gs/capture.py` | 启动Gazebo、从SDF读外参、使用/use_sim_time与世界计划 | 新建独立实机采集入口，读取真实标定/驱动，不复用仿真自动巡检启动流程 |
| `integration/lio_dataset/sensors.py` | 当前LiDAR处理写死sim PointCloud2分支 | 接真实消息和点时间，保留RGB原始采集header |
| `integration/lio_dataset/collector.py`、`poses.py` | 有逐图时间关联/实测点记录逻辑，默认若干frame/topic名称 | 参数化话题/帧/真实外参，验证同一时间域 |
| `integration/lio_gs/dataset.py` | 非零D拒绝；要求数据与验收记录；几何门槛检查 | 实机去畸变与完整性记录适配，不伪造passed文件绕过检查 |
| 仿真覆盖审计 | 使用冻结世界mesh和已知目标 | 实景没有该仿真参考；另定实际采集区域/实测覆盖检查，有独立参考时才作几何精度评价，不能沿用仿真85633目标声称全覆盖 |
| `integration/lio_gs/train.py`、原生查看器 | 已对仿真导出输入运行 | 真实数据接口通过后复用，尚未验证实机效果 |

## 后续适配所需信息

系统已按20.04/Noetic处理。后续需要机载电脑CPU/架构/RAM/SSD、相机型号/镜头/快门与驱动/分辨率/时间戳来源、实际安装与已有标定、MID360驱动配置和各话题类型、是否具备触发/PTP等同步条件。一小段真实录包可核对上述接口。飞控型号/固件/定位接入方式用于后续飞行控制与自动采集适配；不阻碍先手持/地面验证离线重建链。
